# USB-CAN / M31 台架模式

## 开关与接线前提

- `src/application/test/can_io_test_config.h` 中 `PJ_BENCH_MODE=1` 时，只启动台架任务和现有 CAN 服务；不启动 `App702`、正式控制轴、`Io702` 或 PWM 任务。改为 0 后恢复原有启动路径，`output_ready=false` 保持不变。也可在 `build_opt.h` 用 `-DPJ_BENCH_MODE=0` 覆盖。
- `PJ_DO_LEVEL=-1` 表示现场吸合电平未知：允许 CAN、DI、AI 测试，拒绝全部 DO 写入。核实 M31 线圈 `true` 对应吸合才改为 1；核实 `false` 对应吸合才改为 0。可用 `-DPJ_DO_LEVEL=1` 或 `=0` 覆盖。不得按软件中的 `FF00` 推断接线后的继电器吸合极性。
- 确认 DO 电平后，M31 网络就绪时任务先对四路逐一写入断开状态；四次均确认成功才接受点动。M31 默认地址为 `192.168.3.7:502`、Unit 1，取自现有 `NetworkConfig`。未联网、启动断开写入失败或极性未知时不会点动。M31 上电到网络就绪前的物理输出状态由 M31 本身决定，软件无法在无网络时保证断开。
- 台架 CAN 使用板载 GPIO15/16 的现有 TWAI 驱动，250 kbit/s，29 位扩展 ID，经典数据帧，DLC=8。USB-CAN 接口须接到 CAN 收发器侧并正确终端匹配。本模式不使用 AO、PWM 或未配置 SPN/FMI 的报警。

## 帧格式

请求 ID `0x18FF7020`，应答 ID `0x18FF7021`；均须选择扩展帧、数据帧、DLC 8，不用 CAN FD 或远程帧。正式 702 指令 ID 为 `0x04069001/81/02/82`，与台架 ID 不重合。

请求 8 字节：`A5 OP CH TIME_LO TIME_HI SEQ 00 XOR`。最后一字节是前 7 字节异或 `5A`。`OP`：01 状态，02 DI，03 AI，04 点动，05 全断开。AI 的 `CH=0` 返回 AI1～AI8 八帧，`CH=1..8` 返回一路。点动 `CH=1..4`、`TIME=1..200` 毫秒，小端；其它命令 `CH/TIME` 按下表为零。其余字节或 ID/DLC 错误都不执行动作。错误的专用 ID 载荷在总线可用时返回错误帧；其它 ID 不返回应答，点动期间收到其它扩展数据帧会触发断开。

应答 8 字节：`5A (OP|80) CH CODE SEQ LOW HIGH XOR`。最后一字节是前 7 字节异或 `A5`。`CODE=00` 表示本次软件/Modbus 事务成功；`01` 帧错误，`02` M31 网络不可用，`03` DO 极性未配置，`04` 断开状态未确认，`05` 忙或重复点动序号，`06` CAN 非正常状态，`07` 请求已过期，`08` 写入时间超出点动期限。`21..28` 对应 M31 `IoResult` 错误 1..8；其中 `26` 为 Modbus 超时、`25` 为连接失败、`28` 为其他 Modbus 错误。CAN 故障时可能无法送出应答，应同时看串口 `BENCH` 日志。

## 可直接输入 USB-CAN 软件的发送表

下表每行均用扩展 ID `18FF7020`、经典数据帧、DLC 8。查询数据取决于实际现场值，后面的示例给出完整编码。

| 作用 | 8 字节发送数据 | 预期应答 |
|---|---|---|
| 状态查询 | `A5 01 00 00 00 01 00 FF` | `18FF7021: 5A 81 00 00 01 FLAGS DETAIL XOR` |
| DI1～DI4 | `A5 02 00 00 00 02 00 FF` | `18FF7021: 5A 82 00 CODE 02 STATE VALID XOR` |
| AI1～AI8 一次查询 | `A5 03 00 00 00 03 00 FF` | `18FF7021` 八帧，分别 `5A 83 CH CODE 03 RAW_LO RAW_HI XOR` |
| AI1 | `A5 03 01 00 00 21 00 DC` | `5A 83 01 CODE 21 RAW_LO RAW_HI XOR` |
| AI2 | `A5 03 02 00 00 22 00 DC` | `5A 83 02 CODE 22 RAW_LO RAW_HI XOR` |
| AI3 | `A5 03 03 00 00 23 00 DC` | `5A 83 03 CODE 23 RAW_LO RAW_HI XOR` |
| AI4 | `A5 03 04 00 00 24 00 DC` | `5A 83 04 CODE 24 RAW_LO RAW_HI XOR` |
| AI5 | `A5 03 05 00 00 25 00 DC` | `5A 83 05 CODE 25 RAW_LO RAW_HI XOR` |
| AI6 | `A5 03 06 00 00 26 00 DC` | `5A 83 06 CODE 26 RAW_LO RAW_HI XOR` |
| AI7 | `A5 03 07 00 00 27 00 DC` | `5A 83 07 CODE 27 RAW_LO RAW_HI XOR` |
| AI8 | `A5 03 08 00 00 28 00 DC` | `5A 83 08 CODE 28 RAW_LO RAW_HI XOR` |
| DO1 左升 100 ms | `A5 04 01 64 00 11 00 8F` | 成功写入 `5A 84 01 00 11 01 01 6B`；自动断开 `5A 84 01 00 11 00 02 69` |
| DO2 左降 100 ms | `A5 04 02 64 00 12 00 8F` | 成功写入 `5A 84 02 00 12 02 01 68`；自动断开 `5A 84 02 00 12 00 02 69` |
| DO3 右升 100 ms | `A5 04 03 64 00 13 00 8F` | 成功写入 `5A 84 03 00 13 03 01 69`；自动断开 `5A 84 03 00 13 00 02 69` |
| DO4 右降 100 ms | `A5 04 04 64 00 14 00 8F` | 成功写入 `5A 84 04 00 14 04 01 6E`；自动断开 `5A 84 04 00 14 00 02 69` |
| 四路全断开 | `A5 05 00 00 00 15 00 EF` | 四次 Modbus 断开写入均成功：`5A 85 00 00 15 00 00 6F` |

`FLAGS` 位：bit0 M31 网络就绪、bit1 DO 极性已配置、bit2 四路断开已确认、bit3 断开写入故障、bit4 CAN 正常、bit5 台架模式。通常配置好且全部就绪时状态应答为 `5A 81 00 00 01 37 00 48`；当前默认极性未知但网络/CAN 正常时为 `5A 81 00 00 01 31 00 4E`。`DETAIL` 在断开故障时为失败 DO 编号，否则为当前点动 DO 编号或 0。

DO 点动应答的 `LOW` 是当前请求吸合的 DO 编号，断开后为 0；`HIGH` 为阶段：1 写入吸合已确认、2 到时或故障触发断开、3 新指令提前断开、4 写入异常。一次点动正常会有两条应答。出现吸合写入异常时，可能先看到阶段 4 的断开结果，再看到原吸合写入的 M31 错误码。这里的“确认”只表示 Modbus 写入应答，不是 DO 物理电压或执行机构反馈。

DI 应答的 `STATE` bit0..3 对应 DI1..DI4 的原始电平；`VALID` bit0..3 表示每路本次读取成功。四路均读到 0 且均有效的完整示例：`5A 82 00 00 02 00 0F 70`。任何读取失败时相应有效位为 0，`CODE` 是首个 M31 错误。DI1/DI2/DI3/DI4 分别映射主油箱低液位、主油箱高温、左滤堵、右滤堵；这里不把原始电平解释为报警。

AI 应答 `CODE=00` 才表示本次原始电流有效；`RAW_LO/HIGH` 是有符号 16 位小端整数，单位 µA，不做 4～20 mA 标定。读取失败时原始值为 `FF FF` 且 `CODE` 非零。AI1=12000 µA 的完整应答示例：`5A 83 01 00 21 E0 2E 92`。AI1～AI8 顺序为左阀芯、左倒斗、左转舵、左压力、右阀芯、右倒斗、右转舵、右压力。

当前 `PJ_DO_LEVEL=-1` 时，DO1 点动应答为 `5A 84 01 03 11 00 00 68`；DO2～DO4 依次为 `5A 84 02 03 12 00 00 68`、`5A 84 03 03 13 00 00 68`、`5A 84 04 03 14 00 00 68`，均不写 M31。全断开也返回 `CODE=03`。配置极性并确认 `FLAGS` 的 bit2 后才使用成功应答列判断点动。

## 测试顺序与失败判断

1. 先核实 M31 DO 吸合电平，再编译台架固件；由你烧录。在负载隔离或可控台架上验证。连接 USB-CAN 并设置 250 kbit/s、扩展帧、经典 CAN。
2. 先发状态查询；检查 bit0、bit1、bit2、bit4 均为 1。bit1 为 0 时仅测试 CAN/DI/AI。再发 DI、AI 查询，核对有效位和原始电流。
3. 依次单发 DO1、DO2、DO3、DO4，每条使用不同 `SEQ`，观察写入确认和断开确认。USB 软件关闭周期自动发送；重复同一 `SEQ` 不会再次点动。中途发送任何新测试指令会提前断开当前一路。最后发全断开。
4. 没有应答：检查 CAN 波特率、29 位扩展格式、终端电阻、板载 CAN 状态和串口日志。`CODE=02` 查 W5500/M31；`03` 查极性配置；`04` 或状态 bit3 查断开写入；`21..28` 查 Modbus 连接或设备异常。断开失败后禁止新点动，后台继续尝试四路断开。

点动期限从发出吸合 Modbus 请求前开始计时；点动期间不执行 DI/AI 读取，单个任务串行写 M31，截止时间、CAN 超时、总线故障或无效指令都优先触发断开写入。M31 `set_do` 是同步 TCP/Modbus 调用，连接或响应异常时可能阻塞超过请求时间；写入确认也只表示 M31 接受了线圈命令，不能证明继电器或油缸动作。因此物理释放时间无法仅靠此软件保证严格不超过 200 ms。需要硬性 200 ms 上限时，应在 M31 或外部硬件增加独立失电定时保护。DO 回读和写入确认均不能作为阀芯、油缸的实际动作反馈。
